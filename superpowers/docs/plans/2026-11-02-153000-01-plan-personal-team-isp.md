# Personal/team static ISP separation

**Goal:** Bind new private ISP A to ITL for the personal profile and ISP B to ASMU for the colleague profile; all dedicated-egress traffic stays on its assigned server and IP, while ordinary GitHub/Codex/general routes retain their contracts.
**Why planning is required:** Live changes across two servers, credential-bearing client exports and persistent routing configuration.
**Authorization:** User supplied two purchased proxy endpoints after approving ITL/personal and ASMU/colleague separation. Map the first supplied endpoint to ITL and the second to ASMU. Credentials and addresses remain outside Git and tool output.
**Acceptance:** Test each new ISP only from its assigned server; verify distinct expected exit identities without printing addresses; back up all changed private configs and service state before mutation; preserve exact canonical domain rules, ordinary routes and original protocol listeners; update sing-box renewal sources as well as live configs. Narrow every dedicated TCP/UDP group per profile to its assigned server, remove ordinary Gemini fallbacks, prevent unsupported UDP from escaping, preserve Mac/iOS display conditions, and syntax-check both profiles. Verify real public protocol requests and server egress identity, persistence under synchronization/renewal merge, current Mac reload without engine restart, and colleague export without personal MITM CA, tailnet enrollment or controller secrets. Do not expire/delete the old proxy subscription or send the colleague file externally.

### Outcome 1: Preflight and staging
- Work: Inspect current owning config/service files and policy routing; save root-only server snapshots and local private profile baseline. Stage new ISP credentials only on their assigned servers. Prefer the supplied HTTP endpoint; use the provider's documented SOCKS5 port only if authenticated TCP and UDP tests prove it works on that same server.
- Verify: Repeated IP-echo through new upstream, target HTTPS responses, source-route stability, binary syntax checks and selected-protocol tests. Treat 403 HEAD as reachability only; authenticated browser checks are separate.
- Stop/recovery: No live mutation if new endpoint/authentication/identity checks fail. Preserve prior routes and snapshots; never test either assigned upstream from the other server or local Mac.

### Outcome 2: Server activation
- Work: Replace only the dedicated-egress outbound on each server, including Xray and sing-box persistent source/runtime configurations. Existing domain sync remains owner. Remove reliance on the old cross-server dedicated-egress bridge only after new local paths pass.
- Rollout: ITL first, validate all supported routes, then ASMU; stop before subsequent rollout if syntax, service health, IP identity or target checks fail. Stage under isolated loopback test ports before touching live services. Restart only changed cores when required, with explicit automatic restoration on activation failure; never restart Surge engine.
- Verify: Expected IP via forced-dedicated health ingress and domain routing, exact rules match canonical source, normalized renewal merge matches runtime, services active, ordinary controls unchanged. On failure restore only task-changed configs and affected services from per-host snapshots.

### Outcome 3: Profile generation and delivery
- Work: Implement a credential-free renderer for per-role dedicated groups from an existing private profile. Personal uses ITL aliases only; colleague uses ASMU aliases only. Keep common definitions available for ordinary traffic. Do not imply full per-user authorization isolation; these are assigned routing profiles. Colleague export removes personal tailnet, CA/controller material, private host aliases and dependent management rules. Proxy connection credentials are intentionally retained for authorized colleague use.
- Verify: Focused renderer tests, candidate profile and both platform projections checked by Surge, no cross-server dedicated/ordinary fallback members, no upstream ISP secrets exported, no personal admin/enrollment secrets in colleague file. Real requests select assigned groups and expected egress. All temporary test services/rules removed. iOS and the colleague's physical client remain explicit acceptance limitations.

### Verified preflight decision
- Both assigned servers successfully authenticated to their assigned HTTP endpoint and provider-documented SOCKS5 endpoint. Both returned the expected assigned IP. SOCKS5 UDP DNS round trips also passed on both hosts, so use the verified SOCKS5 port for persistent routing rather than losing UDP with HTTP CONNECT.
- Default routes to the new providers currently use WARP. Bind only the dedicated outbound's source to each server's physical address (existing source-routing rules select its physical interface); stage and verify that binding before live activation. Do not add global routes or change ordinary egress.
